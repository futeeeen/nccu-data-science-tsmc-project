Why it matters

股價模型不只要猜漲跌，更要知道什麼時候值得進場。

單純提高 Accuracy 不一定能避開關鍵跌勢，也不一定能抓到波段行情。這個專案把「資料來源、訓練標籤、模型分數、交易規則」放在同一個畫面裡檢查。

01

模型可能只學到平庸盤整

如果大多數日子都沒有明顯趨勢，模型可能把不進場預測得很好，卻錯過真正影響績效的轉折點。

02

資料面向會互相衝突

技術面、基本面與籌碼面可能同時給出不同訊號，所以需要拆開看，再決定如何加權或交給 Meta model 學習。

03

回測績效需要被拆解

總報酬、Sharpe、最大回撤、holding ratio 與 entry count 要一起看，才知道策略是有選擇性還是接近買進持有。

Product journey

從資料取得到交易訊號，每一步都能回頭檢查。

Data pipeline

價格、EPS、三大法人與融券資料進入同一條時間線。

價格資料提供 OHLCV，FinMind 或 CSV 補上 EPS 與籌碼流向；基本面會依財報可取得日期對齊，降低未來資訊滲漏。

Three strategy families

同一個研究問題，分成三個可維護的策略版本。

你可以把它想成由簡到繁的實驗階梯：先建立技術面 baseline，再加入多因子，最後用 Triple Barrier 對齊更接近交易目的的標籤。

Baseline

Technical Strategy

只使用技術指標與多模型比較，適合當作最小可比較基準。

Deployed

Multi-Factor Strategy

加入 EPS 與籌碼資料，使用人工加權分數與 Meta model 對照。

Research

Triple Barrier Strategy

用 ATR 動態門檻與事件權重，讓模型更重視波段與關鍵轉折。

Technical Strategy：先確認技術指標能不能形成穩定訊號。

輸入 RSI、MACD、均線乖離、成交量變化等特徵，透過時間序 train / validation / test 切分評估模型與回測結果。

Architecture

架構上保持三個子專案獨立，但讓觀念與介面維持一致。

Data adapters

下載價格、讀取 FinMind、接收手動 CSV，上雲時支援 Streamlit secrets token。

Feature engine

產生技術、基本面、籌碼、ATR 與 Triple Barrier event 欄位。

Model layer

子模型輸出 raw probability，再以 validation percentile 校正成 0-100 分數。

Dashboard

提供架構圖、訓練資料、Glossary、策略比較、訊號下載與回測圖表。

Interactive demo

調整策略假設，看看訊號如何改變。

這裡是介紹頁的小型互動模型，不取代正式 Streamlit 回測；它用來快速理解不同策略版本的設計差異。
